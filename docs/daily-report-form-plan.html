Daily Vessel Report Form — Perfection Plan

Make the web form the single trusted way captains file their daily report — same results as today's PDF imports, restored PDF export for email, and a form UI you can actually read. · 29 Jul 2026
The one-sentence goal A captain who fills this form produces exactly the same data the PDF importer produces today — same map playback, same hour breakdowns, same idle numbers — plus a one-click official PDF to email, with far fewer chances to make the mistakes the paper form allowed.

The form already covers ~90% of what the 256 imported reports contain. Audit of every imported report found these gaps:

Parity guarantee (how we know results are "the same") The form must submit the identical JSON shape the PDF importer writes (data/daily-report.schema.json). Everything downstream — the map, the vessel sheet, the idle math — reads that JSON and never knows whether it came from a PDF or the form. Verified by a round-trip test (Section E).

BData quality — be better than the PDF

Everything vague in today's analytics traces back to weaknesses of the paper form. The web form is the chance to fix them at the source, without changing the official KOC codes.

B1. Location on every task row (the single highest-value change)

Today the app guesses the location of each log row from the free-text description — and succeeds on only ~35% of 4,835 rows. Add to each row:

  • A "Where?" dropdown — the known locations (OPH, OD-1, NSBP, Shuaiba B20/B4…) plus "at sea" and free text. Auto-carried from the previous row so it's one tap, not 25.
  • For transit codes (I01/I02): From → To dropdowns instead, which is what actually drives the vessel across the map.

B2. Activity type next to the code (kills the "Other" black hole)

1,268 of 4,835 rows use code O1 "Other"; bunkering has no code at all and hides inside cargo codes. Add one optional "What kind of job?" dropdown per row — Cargo, Water bunkering, Diesel bunkering, Base-oil, Crew transfer, Tank cleaning, Inspection, Maneuvering, Waiting — stored in a new optional field, while the official code stays untouched for compliance. Auto-suggested live from the description using the same classifier the analytics already use, so usually zero extra typing.

B4. Draft safety

A captain filling 25 rows on a moving vessel must never lose work: auto-save the draft locally on every keystroke, restore it on reopen, and keep a per-vessel template ("start from yesterday's report") so a typical day is edit-3-rows, not type-25.

CPDF export — restore the lost feature

Where it went The feature exists in the legacy pre-React app: admin.js → generatePdf() builds a 4-page print-perfect replica of the official Halliburton "Daily Vessel Report" template (pink headers, tank table, codes legend, sign-off page) and opens the browser's Print → Save-as-PDF. When the app was rebuilt in React, the Forms tab was ported but this button never was. Nothing was deleted — it just lives in a file the new app no longer loads.

Plan:

  1. Port buildReportHTML() from admin.js into the React client as a standalone module (it's self-contained HTML+CSS generation; near copy-paste).
  2. "🖨 Generate PDF" button in two places: on the form (current entries, even before submitting) and on every saved report in the Daily Reports tab — so old imported reports can be re-printed too.
  3. Same flow as before: opens a print-ready window → captain hits Print / Save as PDF → attaches to email. No new libraries, works offline.
  4. Extend the template with the Section-A additions (drill water / base oil rows already exist in its tank table — wire real values in instead of dashes).
  5. File-name convention matching today's email attachments (e.g. CA3 DVR 06-05-2026.pdf) shown in the window title.

DUI — make the form readable

Today the form is a wall of same-looking white fields. Changes, in both light and dark themes:

  • One color per section. Each card gets a colored left border + tinted header strip with an icon: Header (blue), Safety (red), Task log (purple), Consumables (teal), Deck cargo (amber), Provisions (green), Sign-off (slate). You always know where you are.
  • Inputs that look like inputs. Visible borders, subtle field background distinct from the card, clear focus ring, units ("M³") rendered inside the field edge instead of placeholder text.
  • Task-log rows carry the code's color — the same palette the map and vessel sheet already use: standby amber, transit blue, cargo green, downtime red. Zebra striping + sticky header for 25-row days.
  • Coverage bar (from B3) doubles as the visual anchor of the task log: a 24-hour strip filling with each row's color as the day is accounted for.
  • Required vs optional made obvious: required labels bold with a dot, optional ones muted — instead of everything looking equally important.

EHow we prove it's right

  1. Round-trip test: load an existing imported report (e.g. CA3 2026-05-06), prefill the form with it, submit, and diff the produced JSON against the original — must be identical apart from the source stamp. Automate for all 256 reports.
  2. PDF golden test: generate the PDF from an imported report and compare side-by-side with the captain's original email PDF.
  3. Analytics regression: the vessel-sheet totals (1063h 11m at OPH, etc.) must not move at all after the form changes ship.
  4. Browser verification: run the app, fill a report end-to-end including deliberate mistakes (gap in the day, typo attempts), screenshot light + dark.
